# Salonify 概要 — このアプリは何か

このドキュメントは、Salonify というアプリケーションが「何であるか」を、経緯や参照実装を知らない人にも単体で伝わるようにまとめたものです。要件（`docs/reference/requirements.md`）、実装指示（`docs/instructions/`）、そして実際のコード（`app/` 配下）を突き合わせて、**何が本物で・何がモックで・何が未実装なのか**を正直に整理しています。

> このリポジトリはコードレビュー実演イベント用のデモです。「本番運用できる完成品」ではなく、**意図的に奇妙な仕様や未実装部分を含んだ題材**である点に注意してください（後述）。

---

## 1. このアプリは何か

**Salonify は「オンラインサロン・プラットフォーム」のデモ実装**です。誰でもオンラインサロンを開設・運営でき、会員は月額プランに加入してコンテンツとコミュニティに参加できる、マルチテナント型の Web サービスです。

主な柱は次の 5 つです。

- **サロン開設**: 誰でもサロン（名前・キャッチコピー・説明・カテゴリ・公開設定・料金プラン）を作れる
- **プラン課金**: 会員は月額プランを選んで入会する（トライアル期間・初月割引に対応）
- **会員限定投稿**: オーナーが Markdown で記事を投稿し、プランごとに公開範囲を絞れる（画像アップロード・YouTube 埋め込み対応）
- **掲示板**: 会員がスレッドを立て、コメント（1 段ネスト）・いいね・通報ができる
- **管理機能**: オーナー向けの運営ダッシュボード（売上見込み・会員管理・振込申請）と、プラットフォーム管理者向けのユーザー/サロン/通報管理

技術的には **Java 21 / Spring Boot 3.5 のサーバーサイドレンダリング（Spring MVC + Thymeleaf）** で作られています。更新系はすべて「HTML フォーム POST → 処理 → 303 リダイレクト（PRG パターン）」です。認証・認可は **Spring Security 本体を使わず、JWT Cookie + Interceptor + 自前ガード**で実装しています。外部サービス（決済・メール・画像ストレージ）にはデフォルトで接続せず、ローカルで完結します。

## 2. 登場ロールとできること

ユーザーに固定の「役割」テーブルがあるわけではなく、**状況に応じて役割が決まる**点が特徴です（同じユーザーが、あるサロンではオーナー、別のサロンでは会員になり得ます）。

| ロール | 判定 | 主にできること |
|---|---|---|
| **ゲスト（未登録／未ログイン）** | セッション Cookie 無し | トップ閲覧、サロン一覧・検索、各サロンの LP 閲覧、新規登録・ログイン |
| **会員（ログイン済みユーザー）** | 有効な `session` Cookie | プロフィール編集、サロンへの入会・プラン変更・退会、支払い履歴閲覧、（加入サロン内で）投稿閲覧・掲示板の投稿/コメント/いいね/通報 |
| **サロンオーナー** | `salon.ownerId == 自分` | 自サロンの作成・編集、プラン管理、投稿の作成/編集/削除、会員管理（プラン変更・強制退会）、招待 URL 管理、売上・振込申請の閲覧。自サロンには常にメンバーとしてもアクセス可 |
| **プラットフォーム管理者** | `user.isAdmin == true` | ユーザー管理（検索・停止・管理者付与）、サロン管理（削除）、通報管理（解決マーク） |

ロールごとのアクセス制御は 3 つのガードで表現されます（`app/.../support/Auth.java`）。

- `requireSalonOwner(salonId)`: 未ログイン→`/login`、サロン無し→404、**オーナー本人以外→404（403 ではなく「存在を隠す」）**
- `requireSalonMember(salonId)`: 未ログイン→`/login`、サロン無し→404、オーナーは常に可、それ以外は当該サロンの `active` メンバーでなければ `/salons/{id}` へ戻す
- `requireAdmin()`: 未ログイン or 非管理者→`/` へ

## 3. 機能ごとの実装状況

凡例:
**本物** = 実際にその処理が動く / **モック** = 動いているように見えるが外部連携や実処理はしない / **二段構え** = デフォルトはモック、キー設定時のみ実連携 / **未実装** = 存在しない（多くは意図的なスコープ外）

### 認証・アカウント

| 機能 | 状況 | 補足 |
|---|---|---|
| メール認証付き新規登録 | 本物（メール送信のみモック） | 6 桁コードを発行し、**確認画面に直接表示** + ログ出力（`[DEV] verification to=... code=...`）。この時点では User を作らず、コード検証成功時に初めて User を作成 |
| ログイン（JWT Cookie） | 本物 | JWT HS256 / ペイロードは `{uid}` のみ / 有効期限 30 日 / BCrypt strength 10。**stateless**（サーバー側セッション無し、ログアウト = Cookie 削除） |
| パスワードリセット | 本物（メール送信のみモック） | コードは確認画面に表示 |
| 退会処理 | 本物 | ハード削除せず、email/passwordHash/displayName を匿名値に上書きし、全 Membership を `cancelled` に |
| プロフィール編集 | 本物 | displayName / bio / avatarUrl |
| レート制限 | 本物 | **プロセス内メモリ（ConcurrentHashMap）の固定ウィンドウ方式**。分散環境では効かない |

### サロン・投稿・掲示板

| 機能 | 状況 | 補足 |
|---|---|---|
| サロン開設・編集 | 本物 | 公開設定は「公開」「招待 URL 限定」の 2 択（後述の食い違い参照） |
| 料金プラン（複数・トライアル・初月割引） | 本物 | 価格は 0〜100,000 にクランプ、トライアル 0〜30 日 |
| 招待 URL | 本物 | `invite` サロンで招待コードを発行・無効化。利用上限・有効期限に対応 |
| 投稿（Markdown・下書き・ピン留め・プラン限定） | 本物 | フォーム名は `bodyHtml` だが中身は Markdown（後述）。保存時に HTML 変換 + サニタイズ |
| 画像アップロード | 本物（保存先はローカル） | クラウドではなくコンテナ内 `/app/uploads`（docker volume）に保存し `/uploads/**` で配信。4MB 上限、`image/jpeg,png,gif,webp` のみ |
| YouTube 埋め込み | 本物 | 正規表現で 11 文字 ID を抽出して iframe 化 |
| HTML サニタイズ | 本物（ただし正規表現ベース） | ホワイトリスト方式。参照実装の移植で、**本番グレードではない**旨がコード内に明記 |
| 掲示板（スレッド・コメント 1 段ネスト・いいね・通報） | 本物 | 掲示板本文は「表示時に」Markdown 変換 + サニタイズ（投稿とは方式が違う） |
| オーナー・ダッシュボード（売上見込み・会員数・投稿数） | 本物 | 月次売上見込み = Σ（プラン価格 × その active 会員数） |
| 会員管理（プラン変更・強制退会） | 本物 | いずれも DB のステータス変更のみ |
| 管理者機能（ユーザー/サロン/通報） | 本物 | 停止は passwordHash 上書き（後述）、サロン削除は Cascade |

### 決済・課金

| 機能 | 状況 | 補足 |
|---|---|---|
| 入会時の決済 | **二段構え** | `STRIPE_SECRET_KEY` 未設定（デフォルト）→ Stripe を使わず即入会。設定時（`sk_test_...`）→ Stripe Checkout（テストモード）へ遷移し `GET /api/join/success` で入会確定 |
| プラットフォーム手数料計算（5%） | 本物 | `platformFee = floor(amount × 0.05)`、`ownerNet = amount − fee`。売上画面で使用 |
| 初回請求レコード | 本物 | 入会時に `firstAmount > 0` なら Invoice（status=`paid`）を 1 件だけ記録 |
| 振込申請（payout） | **モック** | 何も処理せず成功メッセージのみ。振込可能額が ¥3,000 未満のときはボタン無効（手数料計算だけは本物） |
| 定期課金（月次自動更新） | **未実装** | バッチ／スケジューラは存在しない。入会後の再請求は発生しない |
| 支払い失敗リトライ・会員資格停止（dunning） | **未実装** | `MembershipStatus.PAST_DUE` / `SUSPENDED` はコード上定義されているが、**どこからも設定されない** |
| 領収書・請求書 PDF 発行 | **未実装** | — |
| Stripe Webhook / 継続課金・解約・プラン変更のサブスク同期 | **未実装** | 二段構えでキー設定時も、解約・プラン変更は DB のみ更新し Stripe 側には反映されない |

## 4. 意図的に残している「奇妙な仕様」

以下は**バグではなく仕様**です。参照実装（Next.js 製）の挙動を忠実に再現するために、あえて「改善」せずそのまま実装しています。コードレビューで指摘対象になりやすい箇所ですが、**指摘されても直さない前提**の題材です。

| # | 奇妙な仕様 | 実際の挙動 | 場所 |
|---|---|---|---|
| 1 | **権限エラーを 404 で隠す** | オーナーでないユーザーが他人のサロンのオーナー画面にアクセスすると、403 ではなく **404** を返す（リソースの存在自体を隠す） | `support/Auth.java#requireSalonOwner` |
| 2 | **フォーム名 `bodyHtml` に Markdown** | 投稿フォームのフィールド名は `bodyHtml` だが、送られてくる中身は Markdown 原文。サーバー側で HTML 変換 + サニタイズして `bodyHtml` カラムに、原文を `bodyMarkdown` カラムに保存する | `controller/OwnerPostController.java` |
| 3 | **ユーザー停止 = passwordHash 上書き** | 管理者の「停止」は、専用の停止フラグを立てるのではなく **passwordHash を文字列 `"suspended"` に上書き**する。BCrypt 照合が自然に失敗することでログイン不能化する（`suspended` は正しいハッシュではないため） | `controller/AdminController.java` |
| 4 | **停止しても既存セッションは生き続ける** | 上記の停止は「新規ログイン」を防ぐだけ。JWT は stateless で失効させないため、**停止前に発行済みの Cookie は最大 30 日間有効なまま** | `support/Auth.java` / `AdminController.java` のコメント |
| 5 | **ログインは停止・メール未認証を明示チェックしない** | ログイン処理は passwordHash の照合のみ。`emailVerified` や停止状態を明示的に見ない（#3 の副作用で停止ユーザーは自然に弾かれる設計） | `controller/AuthController.java` |
| 6 | **招待 uses の先行インクリメント** | 招待コード検証が通った時点で `uses` を +1 する。**その後のプラン検証などで入会が失敗しても uses を戻さない** | `service/JoinService.java#join` |
| 7 | **掲示板コメントのネスト平坦化** | コメントは 1 段ネストのみ。返信先（parentId）がさらに親を持つ場合、その**ルートに付け替える**（2 段目以降を作らせない） | `controller/BoardController.java` |
| 8 | **掲示板カテゴリは "all" 固定の飾り** | URL の `{categoryId}` は受け取るがフィルタには使わない。Thread にカテゴリ列が無く、どのカテゴリタブでも同じ全件リストが出る | `controller/BoardController.java` |
| 9 | **パスワード忘れで存在が分かる** | 未登録メールで再設定申請すると `?msg=not-found` を返す（存在の有無が判別できてしまう挙動を、あえてそのまま再現） | `controller/AuthController.java` |
| 10 | **プラン変更は DB のみ更新** | active 会員が別プランに変更すると Membership.planId を書き換えるだけ。Stripe 有効時でもサブスク/価格は更新せず、**実請求額と表示額がズレうる** | `service/JoinService.java` |
| 11 | **HTML サニタイズが正規表現ベース** | DOM パーサではなく正規表現でタグ/属性をホワイトリスト処理する。参照実装の移植で、コード内に「本番グレードではない」旨を明記 | `support/Sanitizer.java` |

## 5. 要件と実装の食い違い（正直な一覧）

要件定義（`docs/reference/requirements.md`）に書かれているが、実装では**縮小・省略・未対応**になっている項目です。多くは実装指示（`docs/instructions/`）で明示的にスコープ外とされたものですが、「要件だけ読んだ人」が誤解しないよう洗い出しています。

| 要件（requirements.md） | 実装の実態 | 種別 |
|---|---|---|
| 公開設定は「公開 / 非公開 / 招待制」の **3 種類**（3-2） | UI は「公開 / 招待 URL 限定」の **2 択**。`SalonVisibility.PRIVATE`（"private"）はコード上「レガシー」として残るが、フォームから設定できず `normalize()` で public に丸められる | 縮小 |
| 会員一覧に「決済ステータス：成功 / 失敗」（3-2） | `InvoiceStatus` は **`paid` のみ**。失敗ステータスは存在せず、会員一覧に「失敗」は決して現れない | 未対応 |
| 月額サブスクリプションの**自動更新**・初回課金→翌月以降自動引き落とし（3-3） | 定期課金バッチが**存在しない**。入会後の再請求は発生しない | 未実装（スコープ外） |
| 支払い失敗時の**リトライ（3 回）→会員資格停止**（3-3） | dunning 処理なし。`PAST_DUE` / `SUSPENDED` ステータスはどこからも設定されない | 未実装（スコープ外） |
| 領収書・請求書の**自動発行（PDF）**（3-3） | 無し | 未実装（スコープ外） |
| 投稿への**ファイル添付（PDF・ZIP 等）**（3-4） | アップロードは**画像のみ**（jpeg/png/gif/webp、4MB）。PDF/ZIP は不可 | 縮小 |
| 「リッチテキストエディタ」による記事投稿（3-4） | 実体は **Markdown の textarea**（+ 画像挿入ボタン） | 差異 |
| 固定ページ（ウェルカムページ等）（3-4） | 専用の固定ページ機能は無い（ピン留め投稿で代替） | 未対応 |
| 掲示板の**複数カテゴリ**（3-5 の「カテゴリ一覧」） | カテゴリは "all" 固定（#8 参照） | 縮小 |
| いいね / **リアクション**（複数種類）（3-5） | リアクションは `like` トグルのみ | 縮小 |
| 通報・モデレーションの**理由入力**（3-5） | 通報ボタンは固定理由で送信。理由入力 UI は無し | 縮小 |
| サロン LP の**会員数・口コミ**（3-6） | 会員数は表示するが**口コミ機能は無し**（要件上も「任意」） | 未対応 |
| クレジットカード決済（Visa/Master/**JCB/Amex**）（3-3） | デフォルトはモック即入会。キー設定時のみ Stripe Checkout（テストモード） | 二段構え |
| 非機能要件: HTTPS 必須 / 画像・動画の **CDN 配信** / 日次バックアップ / 稼働率 99.5%（4 章） | ローカル完結のデモのため未対応（画像はローカルディスク配信、インフラ要件は範囲外） | スコープ外 |

> 注: 上記の「未実装」の大半は、実装指示（`docs/instructions/README.md` の「スコープ外」や 03 の「実装対象外」）で**意図的に外すと明記された**ものです。要件と実装のギャップ = バグ、ではありません。
